具體修改：

2. 憲章「Governance」：範圍描述同步修改。版本升為 1.1.0（擴充規則，MINOR）。

5. METHOD.md 第 5 節：新增 S7「依已核准 UML 建立架構雛形」。S7 只執行一次，在所有需求 Bolt 的 G4 完成後，依全部已核准的 UML 建立；最後一個 Bolt 的 G5 審查範圍加入程式碼 diff。

7. 追溯表：新增「程式模組」欄位，每個類別或模組標註對應的需求 ID 與 UML 元素。

架構雛形的完成條件：

- 類別圖中每個類別都有對應的程式類別或模組，方法只有簽章，沒有內部實作。
- 主要循序圖的呼叫流程有對應的介面或 API 端點，可以回傳假資料。
- 每個程式檔案用註解標註對應的需求 ID（FR-nn）。
- 不加入沒有需求 ID 的類別或功能。

老師說明期中報告的程式碼「至少需要作出整個專案的架構雛形，內部細節的功能可以留到期末再完成」。每一組都要交一份程式碼。已核准的憲章與 METHOD.md 把實作排除在範圍外，因此需要修改。
